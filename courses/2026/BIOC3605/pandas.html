Comparison

Feature .iloc (Integer Location) .loc (Label Location)
Lookup Mechanism Position-based: Uses exact numerical coordinates (0, 1, 2). Name-based: Uses the actual row/column names.
Example Syntax df.iloc[0:5, 2] df.loc["BRCA1":"EGFR", "expression"]
Slicing Rule Exclusive of the stop number (0:3 grabs 0, 1, 2). Inclusive of the stop name ("A":"C" grabs A, B, and C).
Best Used For Grabbing the “Top 10” rows, or dealing with un-named data. Extracting specific genes, writing reproducible pipelines.
Robustness Highly Fragile. Breaks silently if data changes. Highly Robust. Immune to structural column/row shifts.

What if using for Loops

We can use for loop to achieve exactly the same goal

# Time start
start_time_loop = time.time()

#### Exact code starts here 
# 1. Create an empty list to store the answers
new_values = []
# 2. Loop through every single row in the dataframe
for i in range(len(df)):
    # Calculate the new value for this specific row and appe
    math_result = np.log2(df.loc[i, "expression"])
    new_values.append(math_result)
# 3. Assign the completed list as a new column
df["log_expression"] = new_values

#### Exact code ends, Time end
end_time_loop = time.time()
loop_time = end_time_loop - start_time_loop
print(f"For loop finished in: {loop_time:.2f} seconds")

Advantage of using Pandas

Vectorization (Pandas)

  • Code Clarity: Poor. Using 5 lines to write
  • Time efficiency: Low (0.16s)

For loop (Pandas)

  • Code Clarity: Great. 1 line solution, easy to understand
  • Time efficiency: Fast (0.001s)
  • The time difference will be more prominent when the rows increase

Data wrangling

Motivations

If we manipulate the data with what we have just cover

# Create a copy of df to prevent overwriting  
my_data = df.copy()

# 2. Filter for high expression
my_data = my_data[my_data["expression"] > 50000]

# 3. Talking the log of expression
my_data["expression"] = np.log2(my_data["expression"])

Problems

Colab lets you run the same cell multiple times (by accidentally pressing Shift + Enter twice), this step-by-step approach is highly dangerous.

  • Run 1: Your expression of 60,000 is taking log to log(60000)
  • Run 2: You accidentally run the cell again. Python take log again become log(log(60000))

Other problem

The below code will give you a warning

# 1. Filter the data
high_exp = df[df["expression"] > 50000]

# 2. Try to do math on the filtered data
high_exp["expression_k"] = high_exp["expression"] / 1000

Pandas gives you warning because it isn’t sure if high_exp is a brand-new table or just a “window” looking at the original df

Implication

If between the step 1 and 2 you do some change on df["expression"], high_exp won’t get the updated value

Method chaining

In stead of this messy way, `Pandas’ provide a method chaining approach to make your code clearer. In specific, we will focus on the following methods

  • .query(): Selecting data
  • .mutate(): Adding new column
  • .groupby(): Group data by the designated group
  • .summary(): calculate summary statistics

Example

# The parentheses () tell Python this is one pipeline.
final_df = (
    df 
    .query("expression > 50000 and tissue == 'Cerebellum'")
    .assign(expression_k = lambda x: x["expression"] / 1000)
    # 3. SELECT: Keep only these three columns at the very end
    [["gene", "sample", "expression_k"]]
)

.assign(): Creating or Modifying Columns

.assign()adds new columns and returns a new DataFrame without modifying the original rna table.

# The parentheses () tell Python this is one pipeline.
final_df = (
    df 
    .assign(
        time_hours = lambda x: x["time"] * 24,
        time_min   = lambda x: x["time_hours"] * 60,
        log_exp    = lambda x: np.log(x["expression"] + 1)
    )
)
  • lambda x: : x represents the current state of the DataFrame at that exact step. If you filtered rows in the line above, lambda x: ensures you are calculating on the filtered data.
