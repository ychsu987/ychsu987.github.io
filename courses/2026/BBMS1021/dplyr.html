Why wrangling matters

Raw experiment tables are almost never analysis-ready.

  • Columns may be wide, messy, or split across files
  • We need a clean table: one row per observation, clear columns for predictors/outcomes

dplyr is how we reshape and filter those tables so plots and models can run.

Keep a before/after picture in mind: messy spreadsheet → tidy analysis table.

Transforming data with dplyr

Using tidyverse an “umbrella-package” that installs several packages useful for data analysis which work together well such as tidyr, dplyr, ggplot2, tibble, etc.

Example data - Yeast gene expression

  • Rows = one gene measured in one nutrient-limitation condition
  • Columns = gene name, limiting nutrient, growth rate, expression
  • Numbers = log₂ expression relative to a reference RNA (how strongly that gene was “on”)

We will practice dplyr verbs on this table.

  • Source: Brauer et al. (2008), Coordination of Growth Rate, Cell Cycle, Stress Response, and Metabolic Activity in Yeast.
  • Goal: How does yeast gene expression change with growth rate when a single nutrient is limited?

  • Organism: budding yeast (Saccharomyces cerevisiae)

  • Exposure: rich media except one limiting nutrient — Glucose, Leucine, Ammonia, Sulfate, Phosphate, or Uracil

  • Observations: microarray expression at six growth rates (0.05 to 0.3 h⁻¹)

  • Running example: LEU1 (leucine biosynthesis) is turned up when leucine is starved, then falls as the restriction is relaxed.

  • brauer2007_tidy.csv: teaching subset of the expression table (one row per gene × nutrient × growth rate)

Reading data

# Load the yeast expression table and gene annotation from CSV files for later use.

ydat <- read_csv("https://bdsr.stephenturner.us/data/brauer2007_tidy.csv")

A reminder: Variable assignment

  • Only I use <- to assign or update the value of a variable, then the variable will be updated to the new value.
  • Othersies you just do a calculation and the variable will not be updated.
# Assign the value '50' to the weight object.
weight <- 50
# Print out weight to the screen (50)
weight
# What's the value of weight plus 10?
weight + 10
# Weight is still 50
weight
# Weight is only modified if we *reassign* weight to the modified value
weight <- weight+10
# Weight is now 60
weight
  • For rest of the lecture, I won’t update the ydat object, but instead will show the output of each operation. You can choose to update it if you want to keep the changes.

Pipeline mindset

Without dplyr, if we want to manipulate data, we can still use the following vanilla way to perform the task :

# Title: Base R data manipulation example
# Show how row selection, counting, and column updates work without dplyr.

# Select rows 2 to 5 from the expression table.
ydat <- ydat[2:5,]

# Count how many Leucine-limited and Glucose-limited rows are in the selection.
sum(ydat$nutrient == 'Leucine')
sum(ydat$nutrient == 'Glucose')

# Overwrite the nutrient column with a logical value indicating leucine limitation.
ydat$nutrient = ydat$nutrient == 'Leucine'

Pipe operator |>

To prevent us from keep doing like a matryoshka doll

# Title: Nested function call example
# This shows the same work as a pipeline, but in nested form.
h(g(f(data_frame)))

R by default supports Pipe operator |> We can rewrite the above code as

# Title: Pipe operator example
# Use the pipe operator to write the same 
# steps in a clearer, left-to-right order.
data_frame |> 
  f() |> 
  g() |> 
  h()
# Title: Pipe operator example
# Use the pipe operator to write the same 
# steps in a clearer, left-to-right order.
data_frame <-f(data_frame)
data_frame <-g(data_frame)
data_frame <-h(data_frame)

‘|>’ takes the output from the left hand side and then pipes it to be the first argument of the right function.

Perform summary statistics

Frequently we will need to provide summary statistics for your data, we can use summarize() to do it

# Title: Compute summary statistics

ydat |>
    summarize( # Summarize expression with count, mean, standard deviation, and LEU1 row count.
              n=n(),
              mean_expr=mean(expression),
              sd_expr=sd(expression),
              n_leu1=sum(symbol=='LEU1')
    )
# A tibble: 1 × 4
       n mean_expr sd_expr n_leu1
   <int>     <dbl>   <dbl>  <int>
1 198430   0.00337   0.668     NA

Condition matching

if_else(CONDITION, 'TRUE_VALUE', 'FALSE_VALUE') for dichotomous processing

# Title: Create binary restriction status
# Use if_else() to add a restriction label based on growth rate.
ydat |>
    select(symbol, nutrient, rate, expression) |>
    mutate( restriction = if_else(
        rate == 0.05, "Severe restriction", "Relaxed"
    )) |>
    head(3)

Condition matching

  • case_when(Condition ~~ "Label") to handle sequential logical control
# Title: Create categorical restriction stage
# Use case_when() to assign descriptive labels for selected growth rates.
ydat |>
    select(symbol, nutrient, rate, expression) |>
    mutate( restriction = case_when(
        rate == 0.05 ~ "Severe restriction",
        rate == 0.15 ~ "Moderate restriction",
        rate == 0.3 ~ "Relaxed restriction"

Best practice of data wrangling

  1. The “Read-Write-Verify” Loop

    • Write a step
    • Run it immediately
    • Verify the output

    DO NOT propagate error and raise your hand

  2. Look up documentations

  3. Make your code readable

  4. Trial and error

Groupby multiple conditions

You can group by multiple groups together, but note that they need to be stated in the same group_by() brackets

# Title: Multi-group summary
ydat |>
    group_by(nutrient, rate) |> # Group by both limiting nutrient and growth rate,
    summarize(                   #  then summarize the combined groups.
              n=n(),
              mean_expr=mean(expression),
              sd_expr=sd(expression),
    )
